# Phase 2C handoff: Windows XP x64 OpenGL on GA104

Updated November 13, 2026 after VFIO run `.160`.

## Current status

The latest completed VFIO run `.149` booted and shut down normally. The
explicit GLSL client-array triangle passes on the RTX 3070 with 1,352 green
pixels, confirmed by query, `glReadPixels`, and direct CE readback. CPU tracing
now proves that the Begin/End path stages the expected three positions and
that those bytes are present in the CPU BO shadow at VA `0x160900e0` (offset
224). The `.150` NVC0 snapshot matches the passing array draw in captured
vertex formats, strides, shader bindings, and other state; only the position
array base differs (`0x16090010` for array input, `0x160900e0` for immediate).
The `.151` post-fence GPU download then showed that allocation range contains
only zeros on the GPU, while the CPU shadow contains the expected triangle.
This confirms the immediate vertex buffer was not uploaded before submission.
The cause is now identified: `nvx_drm_submit_pushbuf` flushed writable shadows
before resolving direct NVC0 vertex-address references, so BO `0x16` was omitted.
Revision `.152` resolves references first, then flushes every referenced BO that
is GPU-readable and has a writable CPU shadow.

also preceded its later submission timeout, so that timeout did not explain

The cube test's former "softpipe reference" was invalid: it changed an
environment variable after creating the GL context, then rendered again
through that same context. That cannot switch an existing Mesa screen from
Nouveau to softpipe. The comparison and environment toggle have been removed.
Cube acceptance now relies on actual colored pixel count, visible color faces,
bounding box, GL error state, and newly submitted GPU batches. The no-depth
check requires at least 2,000 colored pixels and new GPU batches, so two black
frames cannot pass. In both `.101` and `.102`, depth and no-depth cases fail at
0 colored pixels.
