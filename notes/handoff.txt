# Phase 2C handoff: XP x64 OpenGL on GA104

Updated November 12, 2026 after hardware test `.37`.

## Status

The XP x64 package builds, passes the XP import/subsystem audit, and boots on
RTX 3070 VFIO. Mesa WGL selects Nouveau and creates a Gallium `pipe_screen` and
NVC0 context. TSC0 uploads and context setup complete. The 2D path and the
standalone NVX 3D clear/draw/semaphore tests pass.

Hardware OpenGL is **not working yet**. Test `.37` reports
`[OPENGL_RESULT] FAIL`, `SwapBuffers failed: 183`, 0 rendered frames, a black
center pixel, and GL error `0x502`. Nouveau reports
`unsupported_count=5 last_operation=0x41` (`DRM_NOUVEAU_GEM_PUSHBUF`). The shim
still rejects nonempty pushbuf submissions; the Mesa Nouveau path therefore
executes no GPU batches. The shim now has an initial bounded translator for push entries, BO references,
and LOW/HIGH relocations; it is still diagnostic-only and does not translate
object bindings/method policy or submit commands. Do not describe this as working accelerated OpenGL
or a working cube.

Latest full log: `test_logs/v3.0.0.37-20261112-143958.log`
Latest guest trace: `notes/nouveau-trace-latest.txt`, copied after shutdown from
`C:\test_accel\nvx_nouveau_trace.log`.

## Issues that still need fixing

1. **Build the batch translator and submission route.** The XP
   `DRM_NOUVEAU_GEM_PUSHBUF` shim rejects every nonempty request. The shim now concatenates bounded push entries, maps BO handles to owned
   BufferIds, and translates LOW/HIGH relocations into NVX relocation records.
   It rejects domain-dependent OR relocations because NVX does not carry enough
   allocation-domain data to reproduce them. This code only feeds structural
   validation; it does not translate object bindings, enforce a method policy,
   or submit. Add those steps through a kernel-owned submit ABI and C56F GPFIFO
   route. Keep an explicit class/method allowlist and kernel-owned fence; never
   forward arbitrary user pushbuffers directly to the channel.

2. **Resolve current batch validation failures.** `.37` records full dword
   captures and validates the assembled batches. Initialization and upload
   streams fail validation while a short setup stream passes. Add a validator
   failure stage/reason to distinguish reference, framing, direct GPU address,
   and relocation failures. All observed requests currently report zero
   relocations. Finish packet/method and BO-role inventory before enabling
   execution.

3. **Add kernel-side validation and execution for the accepted method set.**
   Validate client/session ownership, every referenced BO, GPU address range,
   access type, packet/method allowlist, ordering, and fence behavior. Translate
   only the supported operations into the existing kernel-owned channel,
   CE/GR, and semaphore machinery. Cover initialization uploads, state setup,
   render-target clear, and draw submissions.

4. **Render and verify an actual Mesa draw.** After submission works, verify
   shader/state upload, render-target contents, fence completion, and pixel
   readback using the WGL test. The current independent NVX triangle test does
   not prove Mesa's Nouveau path works.

5. **Fix or isolate WGL presentation.** `SwapBuffers` returns false and the
   test prints Windows error 183 (`ERROR_ALREADY_EXISTS`). This may be a
   downstream symptom of missing GPU execution; determine whether it persists
   after Mesa submits and renders successfully, then fix front/back-buffer
   presentation separately if needed. The GL error `0x502` also needs to be
   rechecked after GPU command execution is available.

6. **Replace GART VA quarantine.** Freed 2 MiB VA slices are currently
   quarantined to avoid stale-translation faults. Implement correct translation
   invalidation or safe VA reuse before repeated workloads; the current policy
   consumes address space.

7. **Measure stability and performance.** Once real OpenGL rendering works,
   run repeated draws/swaps and the cube workload, check for freezes or resource
   exhaustion, and measure frame rate. No hardware-accelerated cube has been
   verified.

## Verified fixes and current test results

- `.31` preserves Nouveau aperture/suffix state after rejected pushbuf requests;
  NVC0 context setup no longer hangs during TSC uploads.
- `.35` fixes BO map access widening. The push BO trace reports
  `map_count=1`, `map_access=WRITE`; adding READ now succeeds for the existing
  shadow.
- `.37` diagnostics copy complete bounded command streams directly from the existing
  CPU shadow under the DRM lock, avoiding an extra map/readback request. Trace
  entries show map result 0 and captured dwords.
- `.37`: XP import/subsystem audit passed; `[2D_RESULT] PASS`;
  `[NVX_3D_RESULT] PASS`; `[OPENGL_RESULT] FAIL`. The full test script exits
  nonzero because it requires hardware OpenGL success.
- `HwVidStartIO` code `0x230830` is `IOCTL_NVX_3D_UPLOAD_BUFFER`; `0x23083c`
  is `IOCTL_NVX_3D_DOWNLOAD_BUFFER`. Repeated upload lines are expected buffer
  traffic, not the cause of `SwapBuffers` failure.

## Build and full hardware test

Build Mesa with installed Meson 1.12.1:

```sh
MESON=/tmp/nvx-meson-venv/bin/meson ./test/build_mesa_xp64.sh
```

Full host/build/VFIO run:

```sh
NVX_AUTO_RETRY=1 NVX_GR_CHANNEL_PROBE=1 NVX_GR_PROMOTE_PROBE=1 \
NVX_GR_SUBMISSION_PROBE=1 NVX_BUILD_MESA_ICD=1 \
MESON=/tmp/nvx-meson-venv/bin/meson ./test/test_full_driver.sh
```

Increment the minor version in `test/test_full_driver.sh` and `dist_full/nvx.inf`
before each hardware test. Keep all Mesa changes external in `mesa_patches/`;
the submodule must be restored clean after builds.
