# NVIDIA GA104 Windows XP x64 OpenGL ICD — Handoff

Updated: November 10, 2026

## Goal and current status

Finish Phase 2C: provide a Windows XP x64 OpenGL ICD with RTX 3070 hardware
acceleration. Mesa is a pinned submodule; project-specific Mesa code stays in
`mesa_patches/`.

Phase 2C is **in progress, not complete**. XP loads the Mesa ICD and normal WGL
applications run, but Antigravity reports Mesa `softpipe`; its normal 100-frame
cube is still CPU rendered. Separately, the restricted WGL-to-miniport bridge
successfully submits bounded diagnostic triangles and reads back verified GPU
pixels. These probes do not constitute a general Gallium hardware driver.

The latest full RTX 3070 run is
`test_logs/v3.0.0.1-20261110-155006.log`. It completed with
`Failures=0 software3d=1` and `Status: SOFTWARE_3D_ONLY`. The startup assertion
count stayed at one, with no MMU or GR channel fault; bounded GR, 2D, and
dual-head checks passed. ABI v6 verified a full-size C797 triangle draw,
five post-draw pixel samples, and fence 136. The normal app remains software:
the post-animation bridge trace rejects its 632x453 viewport because it
exceeds the 64-tile bridge limit.

## Current implementation and constraints

- `mesa_patches/nvx_wgl_bridge.c` is a project-owned, restricted bridge for
  small post-VS triangles/quads with flat colors, supported state, and bounded
  64x16 tiles. It converts Mesa coordinates, clips viewport edges, submits
  GPU clears/draws, waits for fences, reads back, and updates softpipe tiles.
- The bridge now rejects workloads exceeding 64 tiles before allocation or
  submission. This protects the current one-target-at-a-time ABI from the
  roughly 300-tile Antigravity viewport. The intended small 9-tile test and
  one-tile depth/cube probes pass.
- ABI v4 adds `DRAW_TRIANGLES`, with a validated maximum of 36 vertices, plus
  bounded GPU upload and a single kernel-built C797 array draw. The two-triangle
  RTX 3070 probe verifies the operation and fence. Mesa flat-color bridge draws
  now group same-color triangles into batches; the nine-tile pixel probe and
  cube probe pass with this bridge path.
- The ABI v5 work adds an RGBA8 block-linear color-target layout,
  allocation metadata, and a size-aware C797 clear with semaphore and CE
  sample readback. Host layout/validation tests pass and the x64 miniport
  builds. The first hardware run exposed Fermi-vs-Turing GOB ordering in
  readback; `Nvx3dTuringColorPixelOffset()` now matches the Turing 2D sector
  order, and the next hardware run verified the full-size target edge and
  fence. This is still only the C797 clear path, not general rendering.
- ABI v6 adds dynamic full-size-target triangle draws and optional five-pixel
  CE readback verification. Hardware confirmed the draw writes the expected
  pixels, completes its fence, and supports 64x16 tile readback at the
  bottom-right framebuffer edge. The WGL bridge does not yet call these
  full-size operations; they remain a diagnostic ABI, not normal OpenGL
  acceleration. The hardware
  run built with `NVX_ENABLE_GR_SUBMISSION_PROBE=1`; production builds disable
  GR submission by default (`NVX_ENABLE_GR_SUBMISSION_PROBE=0`) and must keep
  that safety gate until a supported channel/context path replaces the probe.
- Miniport arbitrary-color `CLEAR_SURFACE` accepts packed AARRGGBB, converts
  normalized channels to float bits, and compares readback against the exact
  requested color. Hardware confirmed `0xFF1A1A33` across all pixels.
- The normal OpenGL renderer remains `softpipe`. The bridge still consumes
  softpipe post-VS vertices and updates softpipe tiles; it does not translate
  Gallium shaders/state or render ordinary frames to a full-size GPU target.
  Do not describe Phase 2C as done.
- The prior `GetTickCount64` and `qsort_s` imports and Antigravity
  initialization error are resolved in the current package: the XP import
  audit passes for the ICD and test binaries, and Antigravity initializes and
  renders 100 software frames. Remaining compiler warnings are unrelated.
- Mesa's existing NVC0 Gallium driver has the relevant C797/Ampere command,
  surface-layout, and shader-generation code, but it is not presently
  buildable as this XP WGL ICD: upstream's WGL target constructs software
  winsys-backed softpipe (or optional D3D12/Zink), while Nouveau's hardware
  driver depends on its Linux DRM/Nouveau winsys. The missing integration is a
  Windows Gallium winsys/resource/context path backed by the miniport ABI,
  followed by NVC0 driver wiring and resource/fence/presentation support.
- A MinGW Meson configuration with `-Dgallium-drivers=softpipe,nouveau`
  succeeds, and the 27-object `libnouveau_codegen.a` (including NVC0 shader
  generation) cross-compiles. The full Nouveau Gallium library stops in
  Linux-only device/winsys sources (`util/os_mman.h`, `xf86drm.h`). An external
  compile-only `sys/ioccom.h` shim is in
  `mesa_patches/nouveau-xp-include/`; it does not implement DRM or hardware
  access. Treat Nouveau as a read-only reference; a project-owned XP winsys,
  resource, command, and fence layer is the next integration route. Keep
  project changes outside Mesa's Nouveau driver directories.
- Mesa submodule must remain clean; customizations belong in `mesa_patches/`.

## Next work to complete Phase 2C

1. Replace per-call diagnostic target use with reusable full-size color/depth
   resources, buffer updates, batched draws, readback, and presentation. A
   full-size clear and constant-color triangle draw pass, but are not
   connected to WGL or reusable resources.
2. Specify project-owned XP resource, context, mapping, and fence interfaces;
   ABI v6 remains test-oriented and has no general Gallium resource/context
   contract.
3. Implement a project-owned Gallium driver and XP winsys in `mesa_patches/`,
   using Mesa/NVC0 only as a read-only reference for Gallium contracts and
   Ampere methods. Preserve WGL software fallback while bringing up GPU color
   triangle draws.
4. Add reusable full-size block-linear color/depth targets, batched command
   submission, fences, and presentation. Do not route large viewports through
   the existing synchronous per-tile bridge; the 144802 experiment faulted GR.
5. Connect WGL/Gallium to the new resource and draw path, then move ordinary
   OpenGL draws to the project-owned hardware driver. Validate Antigravity
   renderer identity and pixel output without assertion
   growth, MMU faults, or display/2D regressions.
6. Run the full hardware command after each significant integration step.
   Bounded bridge probes remain diagnostic evidence only.
