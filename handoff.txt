# NVIDIA GA104 Windows XP x64 OpenGL ICD — Handoff

Updated: November 10, 2026

## Goal

Finish Phase 2C: provide a Windows XP x64 OpenGL ICD that uses RTX 3070
hardware acceleration. Mesa remains a pinned submodule; all project-specific
Mesa changes belong in `mesa_patches/`.

## Status

Phase 2C is **in progress and not complete**. XP's system WGL loads the Mesa
ICD, and the Antigravity GPU test runs, but its normal OpenGL renderer is Mesa
`softpipe` (CPU rendering). A separate, bounded Mesa-to-miniport diagnostic
path submits GPU work and verifies pixels, but it is not a general Gallium
hardware backend and does not make ordinary OpenGL draws GPU accelerated.

The Mesa submodule is clean. Current project edits are uncommitted in:

- `src_driver/nvx_gsp.c`
- `mesa_patches/nvx_wgl_bridge.c`
- `test/audit_ampere_vertex_shader.py`

## Current blocker: real depth output

The Mesa bridge's bounded depth test still fails. The current diagnostic declares
clip-space Z in the SPH, stores a candidate generic input to clip Z, and stores
the paired value to clip W. The latest hardware run nevertheless produced no
color fragments or depth writes for any tested depth. Its instruction dump
prints zero words because it reads the wrong scratch offset; correct that log
pointer and inspect the actual shader disassembly/register flow before another
hardware run. Do not treat this variant as a working depth path.

Next, determine why the valid generic [0,1] depth input does not yield a
rasterized triangle while the color-only shader does. Then prove non-clear
ZF32 values and front/back ordering before wiring Mesa depth through the bridge.
Relevant depth output is near lines 2160–2240 in the latest run log.
