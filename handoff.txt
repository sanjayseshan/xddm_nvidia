# NVIDIA GA104 Windows XP x64 OpenGL ICD — Handoff

Updated: November 10, 2026

## Goal

Finish Phase 2C: provide a Windows XP x64 OpenGL ICD that uses RTX 3070
hardware acceleration. Mesa remains a pinned submodule; all project-specific
Mesa changes belong in `mesa_patches/`.

## Status

Phase 2C is **in progress and not complete**. XP's system WGL loads the Mesa
ICD, and the Antigravity GPU test runs, but its normal OpenGL renderer is Mesa
`softpipe` (CPU rendering). A separate, bounded Mesa-to-miniport diagnostic
path submits GPU work and verifies pixels, but it is not a general Gallium
hardware backend and does not make ordinary OpenGL draws GPU accelerated.

The Mesa submodule is clean. Current project edits are uncommitted in:

- `src_driver/nvx_gsp.c`
- `mesa_patches/nvx_wgl_bridge.c`
- `test/audit_ampere_vertex_shader.py`

## Current blocker: real depth output

The Mesa bridge's bounded depth test still fails. Earlier variants that sourced
clip Z from the generic attribute did not change depth readback: ZF32 stayed at
zero and the first draw won every depth comparison.

The current diagnostic changes clip-Z output to use R11, which the vertex shader
loads from input position Y. In the latest hardware run this clipped all
fragments and left the depth target at its clear value 1.0. This demonstrates
that the added `AST a[0x78]` clip-Z output affects rasterization, but the chosen
source values are outside the active clip range and do not produce a successful
depth-tested draw. The experiment is diagnostic only and remains uncommitted.

Next, feed a valid, controlled [0,1] depth value through the proven clip-Z
output path, verify actual non-clear ZF32 values and front/back depth ordering,
then connect Mesa's depth input to that path. Keep the shader input and clip
ranges within the existing bounded ABI. The last run's relevant entries are
near lines 2160–2240 of `test_logs/v3.0.0.1-20261110-113552.log`.
